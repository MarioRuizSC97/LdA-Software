# Production mode on lda-inventory-dev-mx (Phase A)
Objective: let the app and backend run against the real Firebase project `lda-inventory-dev-mx` (chosen as the production project), without billing: client production mode, project-aware backend guards, and real-project provisioning tooling, all proven against the emulators. Phase B (Blaze, deploy, real users) is out of scope until the user decides.
Branch: feat/production-mode (worktree ~/LdA-Software-worktrees/production-mode, based on 2edfd79). Delivery: ask-on-risk, chain strategy feature-branch-chain (one PR per task stacked inside feat/production-mode). Tests: `flutter test` (Dart), `npm test` in functions/ with the pinned Node 24 runtime.

## Specs
- S1. Client production mode. The app gains a third mode that signs in and runs against `lda-inventory-dev-mx` with `DefaultFirebaseOptions` (lib/firebase_options.dart), reusing the existing gateways and session claims (`role`, `branchId`). Demo and local-emulator modes keep their current behavior; the emulator trusted-app gate and web Auth preinit stay untouched for the emulator path.
- S2. Project-aware backend. Every callable accepts the deployed project `lda-inventory-dev-mx` in addition to the `demo-lda-inventory` emulator, and keeps refusing any other project. Native apps (Android/iOS) are not subject to CORS; web origins stay localhost-only until a production web origin is decided (assumption).
- S3. Real-project provisioning tooling: a script to create/update real users with `role`/`branchId` claims and to seed branches and products, dry-run by default, refusing the demo project and requiring an explicit target. It is not run against the cloud project in Phase A (remote operation not authorized).
- S4. "Fase B, requiere el plan Blaze" stays out of scope: no billing change, no deploy, no remote operation.
