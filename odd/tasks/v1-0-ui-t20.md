# T20 post-T19 apuntes (precision → decimales wording, PIN privacy curtain for intake and cost)
Branch feat/v1-0-ui-t9 at 9eac94e. T20A is copy-only. T20B is a client-side privacy curtain (no backend, rules or stored-server-data change).
Goal: last changes before the production decision.

## Specs

- S1 (wording). "me gustaria que cambiaras en el perfil de detalles de producto el hecho de que aparezca como presición siendo que a la hora de registrar como nuevo el producto aparece en el campo como decimales, ahora si que ahí discrepa en nombres como se ve representado"
- S2 (PIN). "me gustaría ver la posibilidad de poder hacer una especie de autenticacion para poder entrar a registro de entrada algo simple como introducir un PIN y también eso obligaria a que en los detalles del producto se deba ocultar el costo que se tiene por producto, pues te explico la situacion puede que en algun momento un trabajador se vea en la necesidad de accesar al perfil del admin para dar de alta algunos productos ya después un admin haria el alta del registro de entrada y haria que dicho trabajador tenga acceso a información que no debería de conocer como tal, ahora si que evalua como seria conveniente tener eso como un paso extra de privacidad ahí"

## Decisions

- D1 (S1): every user-visible "precisión" becomes "decimales": 'Unidad: X (precisión N)' → 'Unidad: X (decimales: N)' (details sheet, intake panel, transfers form); creation errors 'La precisión es obligatoria.' → 'Los decimales son obligatorios.', 'La precisión debe ser un entero del 0 al 6.' → 'Los decimales deben ser un entero del 0 al 6.', 'Error en la precisión: ' → 'Error en los decimales: '; intake/transfer validation copy likewise. Identifiers/keys (precision, create-product-precision) unchanged.
- D2 (S2, user choice "A ahora + B después"): v1.0 ships a client-side PIN privacy CURTAIN, not a security boundary. The server still serves cost data to the administrator role; anyone with the admin credentials and technical knowledge could bypass it. The real boundary — a separate "Capturista" account/role whose Firestore rules deny cost reads — is a future update (B).
- D3 (S2, user choice "Lo crea el admin en cada equipo"): the PIN (4-6 digits) is created on first use per device and stored only on that device as a salted hash (never plaintext) via shared_preferences; changing it requires the current PIN; if forgotten it is reset by clearing the app data on that device. No server involvement.
- D4 (S2, user choice "Hasta salir del panel"): unlocking is scoped: entering Registrar entrada asks for the PIN; the product details sheet hides every cost line behind a 'Ver costo' action that asks for the PIN; leaving the panel / closing the sheet locks again. Sellers never see costs (unchanged).
