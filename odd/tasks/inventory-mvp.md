# Inventory MVP — implementation tasks

## Objective and constraints
Build a single-company, multi-branch inventory app (`lda_inventory`, `com.ldasoftware`) for Android, iOS, and internal web. Stock is branch-scoped; writes must be online, trusted, transactional, idempotent, auditable, and non-negative. Sellers see only assigned-branch data, never acquisition costs.

- MVP: catalog/QR, stock intake, sales and internal receipts, partial returns, exchanges, warranty states, immediate transfers, destination in-app notices. No offline writes, suppliers, credit, fiscal integration, public commerce, refund reconciliation, or external invoice references.
- Global admin-editable sale price with audit; sales retain their actual price. Latest purchase cost is reference only; each intake retains historical cost. Branch prices, weighted-average costing, margins and profit reports are deferred.
- Local emulator project: `demo-lda-inventory`. Development: `lda-inventory-dev-mx` (Spark, user's personal account), Firestore `(default)` Standard/Native in `us-south1` with rules deployed; `.firebaserc` alias `dev`. All branches/users are in Mexico; development data may reside in the US. Production project/location undecided and requires separate approval. No billing, Blaze, Storage bucket, Functions deploy, push, or production operation authorized.
- Android/web FlutterFire clients work; iOS app registered and plist downloaded, but Dart options and Xcode integration are incomplete. No native builds verified. Full Xcode, CocoaPods, Ruby `xcodeproj`, Android command-line tools/licenses, and Chrome are unavailable. User deferred iOS setup because it is not quick.
