# T15 wide-screen panel distribution (v1.0 final layout pass)

Objective: give every panel a good distribution of elements on wide screens so it no
longer looks empty, while keeping the mobile-first behaviour intact. Presentation only:
no cart/sale logic, stock, pricing, permissions, or dependency changes.

## Decisions (parent, with the user)

- D1. Strategy = TWO COLUMNS + CONTEXT on wide screens; framing-only and widen-only were rejected. Each panel pairs its main column with a second, genuinely useful element (never filler): lists go to a wider/two-column arrangement, forms gain a side card with real context (the selected sale, the transfer summary, a product preview), the cart and receipt gain a summary/context rail.
- D2. Scope = ALL EIGHT panels: cart, Correcciones, Avisos, Crear producto, Movimientos, Traslados, sale receipt, login.
- D3. One shared responsive scaffold in lib/app/ (single source of truth for the breakpoint and column ratios) instead of eight ad-hoc layouts; on narrow widths every panel keeps today's single-column behaviour byte-identically.
- D4. Breakpoint follows the existing compact-bar threshold family used by the catalog (mobile/compact vs wide); the shared scaffold owns it and every panel adopts it.
- D5. Nothing is invented: the context column shows data the panel already has (selected item, totals, counts, previews), or a short, honest help block when the panel has no natural context.
- D6. All Spanish strings and widget keys stay byte-identical; tests assert the new arrangement observably (column presence/absence, widths, order).
